# CLAUDE.md

Soulslike prototype in Rust (Bevy 0.20 + avian3d 0.8 + leafwing-input-manager 0.22).

- **Start every session by reading `ROADMAP.md`** — it holds the design spec, controls, architecture, phase checklist and decision log. Continue at the first unchecked task; tick boxes and log decisions as you go.
- Code map: `character/` = generic movement/actions/stats, `humanoid/` = reusable body + animations (+ `skins.rs`: player skins, look-only on the shared skeleton; `player/skin.rs` swaps them live), `quadruped/` = reusable four-legged body + gaits (the warg), `grab.rs` = creature grabs (pounce → held → bite), `weapon/` = weapon classes (movesets: `light_sword.rs`, `axe.rs`, …) + weapon definitions (models) + hands (`Wielded`: right / left / two-handed, `AttackHand`), `ability.rs` = activated weapon abilities, `player/` = the player built from these, `items/` = item registry, inventory/equipment, pickups, `enemy/` = enemies as data (`kinds.rs`: `EnemyDef` per kind — Hollow, Acolyte, Warg, Mourner, Contorted, the Thorned Saint) + shared brain helpers (`ai.rs`) + `fighter.rs` (humanoid brain with specials) + `beast.rs` (four-legged brain) + `boss.rs` (fog gate, boss bar) + `dormancy.rs` (far enemies sleep); brains write the same intents as input, `level/` = levels built from `assets/levels/*.ron` (lvl1 north of the arena, lvl2 the gothic cathedral south; generated walls, stairs, one-way/locked/sealed doors, torches, spawn points with drops, forgery props, `gothic.rs` props, `riddle.rs` bells, lvl3 the Drowned Library south-east of the Choir with `library.rs` props/traps), `textures.rs` = procedural textures, `lockon.rs` = lock-on, `net/` = online co-op over iroh (host/join codes, puppets, forwarded hits, the host's world in `net/world.rs`), `pvp.rs` = opt-in PvP + usable consumables, `interact.rs` = the shared E prompt, `chat.rs` = chat (T line → notification feed, through the host), `net/names.rs` = player names (defaults, unique twins), `settings.rs` / `save.rs` = settings + key bindings and autosave (OS config/data folders; untouched by autopilot runs), `sound.rs` = synthesised spatial sounds, `ambience.rs` = per-area soundscapes (cross-faded), `critical.rs` = backstabs / ripostes, `light.rs` = the Light currency (+ `ui/light_counter.rs`), `spectate.rs` = watching survivors after falling in a boss fight (online), `ladder.rs` = ladders (climb actions), `projectile.rs` = darts / ink bolts, `healing.rs` / `hearth.rs` = Healing Ale, rest and death/respawn, `ui/` = HUD, notifications, text input, damage numbers, the inventory screen and the Esc menu (player-facing text in `ui/strings.rs`; the Hearth is drawn as a sunflower) (see ROADMAP §4, N13, N15, N17, N18, N19, N20, N21, N22, N23, N24, N25, N27, N28, N29, N30, N31, N32, N34–N38).
- `PROMPT.md` is the user's original request (cleaned up). Treat it as the source of truth for intent.
- Problems and findings go in the **Notes** section of `ROADMAP.md` (N1, N2, …). Check the open ones first.
- Commit every finished step with a descriptive message (no need to ask). Branch when it's useful.
- Keep the game runnable (`cargo run`) at the end of every phase. Gameplay constants go in `src/tuning.rs`; per-weapon-class attack numbers go in `src/weapon/<class>.rs`.
- When running the binary directly (autopilots, screenshots), set `BEVY_ASSET_ROOT=.` so `assets/` is found.
